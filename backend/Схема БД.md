<a name="права-доступа"></a>
### Права доступа (`permissions`)

| Поле        | Тип                | Примечание                                                  |
| ----------- | ------------------ | ----------------------------------------------------------- |
| `id`        | uuid               | PK                                                          |
| `user_id`   | uuid               | FK → `user.id`                                              |
| `survey_id` | uuid               | FK → `survey.id`                                            |
| `role`      | custom type (enum) | роль пользователя в опросе (редактор/может смотреть ответы) |

<a name="пользователь"></a>
### Пользователь (`user`)

| Поле            | Тип                               | Примечание                |
| --------------- | --------------------------------- | ------------------------- |
| `id`            | uuid                              | PK                        |
| `login`         | ? — нужно ли ограничение на длину |                           |
| `email`         | text                              |                           |
| `password_hash` | text                              | хранить только хэш пароля |
| `salt`          | text                              | соль для пароля           |
| `registered_at` | timestamp                         | дата регистрации          |

**Заметки:**

- Cлышал, что uuid лучше, чем автоинкрементальный id с коммерческой точки зрения: конкуренты не будут знать количество юзеров/опросов (через url).
- Предлагаю сразу по-взрослому делать: солить пароли и хранить только их хэш для безопасности.

<a name="опрос"></a>
### Опрос (`survey`)

| Поле                    | Тип       | Примечание                                      |
| ----------------------- | --------- | ----------------------------------------------- |
| `id`                    | uuid      | PK                                              |
| `author_id`             | uuid      | FK → `user.id`                                  |
| `title`                 | text      | заголовок                                       |
| `description`           | text      | описание                                        |
| `is_authorized_only`    | bool      | только для авторизованных пользователей или нет |
| `are_responses_limited` | bool      | можно пройти только один раз или нет            |
| `is_published`          | bool      | черновик или нет                                |
| `expire_at`             | timestamp | дедлайн прохождения                             |
| `created_at`            | timestamp | дата создания                                   |

> При реализации параметры `is_authorized_only`, `are_responses_limited` должны быть связаны между собой.

#### (Возможное) дополнение №1

| Поле        | Тип  | Примечание                  |
| ----------- | ---- | --------------------------- |
| `do_notify` | bool | уведомления о новых ответах |

> Уведы о новых ответах? В Яндекс Формах такое видел, в ТЗ вроде тоже есть.

#### (Возможное) дополнение №2

| Поле | Тип | Примечание |
|------|-----|------------|
| `is_template` | bool | является ли опрос шаблоном |

> Шаблоны? Можно так реализовать (флагом `is_template`), чтобы не делать отдельную сущность. Просто потом копировать этот опрос (вместе с ответами и прочими связанными сущностями), чтобы воспользоваться.

<a name="связи-между-сущностями"></a>
## Связи между сущностями

- `user` 1 — N `survey` (через `survey.author_id`).
- `user` N — N `survey` через `permissions` (`permissions.user_id`, `permissions.survey_id`, `role`).
- `survey` 1 — N `page` (через `page.survey_id`).
- `survey` 1 — 1 `completion` (через `completion.survey_id`).
- `page` 1 — N `question` (через `question.page_id`).
- `question` 1 — N `choice` (через `choice.question_id`).
- `user` 1 — N `response` (через `response.user_id`).
- `survey` 1 — N `response` (через `response.survey_id`).
- `response` 1 — N `answer` (через `answer.response_id`).
- `question` 1 — N `answer` (через `answer.question_id`).

<a name="сквозные-нерешённые-вопросы"></a>
## Сквозные нерешённые вопросы

- **Порядок элементов** (страниц, вопросов, вариантов ответа): порядковый номер или связный список (`id` предыдущего/следующего)?
- **Медиа** (для вопросов и экрана прощания): как хранить?
- **Шаблоны:** отдельная сущность или флаг `is_template` на `survey`?
- **Уведомления** о новых ответах: `do_notify` на `survey`.
