## Сущности 

<a name="права-доступа"></a>
### Права доступа (`permissions`)

| Поле        | Тип                | Примечание                                                  |
| ----------- | ------------------ | ----------------------------------------------------------- |
| `user_id`   | uuid               | PK, FK → `user.id`                                          |
| `survey_id` | uuid               | PK, FK → `survey.id`                                        |
| `role`      | text               | роль пользователя в опросе (редактор/аналитик)              |
| `do_notify` | bool               | уведомлять <u>пользователя</u> о новых ответах или нет      |

**Заметки:**
- Таблицу для хранения информации о пользователях, которых подключают к управлению опросом. Информацию об авторах тут хранить не надо — она и так есть в таблице с самими опросами.

---

<a name="пользователь"></a>
### Пользователь (`user`)

| Поле            | Тип                               | Примечание                |
| --------------- | --------------------------------- | ------------------------- |
| `id`            | uuid                              | PK                        |
| `login`         | varchar(32)                       | ограничение — 32 символа  |
| `email`         | varchar(254)                      | ограничение — 254 символа |
| `password_hash` | text                              | хэш пароля                |
| `salt`          | text                              | соль для пароля           |
| `registered_at` | timestamp                         | дата регистрации          |

**Заметки:**

- Слышал, что uuid лучше, чем автоинкрементальный id с коммерческой точки зрения: конкуренты не будут знать количество юзеров/опросов (через url).
- Ограничение на длину логина — 32 (разумно), на длину почты — 254 (по стандарту, загуглил). 
- Предлагаю сразу по-взрослому делать: солить пароли и хранить только их хэш для безопасности.

<a name="опрос"></a>
### Опрос (`survey`)

| Поле                         | Тип       | Примечание                                       |
| ---------------------------- | --------- | ------------------------------------------------ |
| `id`                         | uuid      | PK                                               |
| `author_id`                  | uuid      | FK → `user.id`                                   |
| `title`                      | text      | заголовок                                        |
| `description`                | text      | описание                                         |
| `is_authorized_only`         | bool      | только для авторизованных пользователей или нет  |
| `are_responses_limited_to_1` | bool      | можно пройти только один раз или нет             |
| `is_published`               | bool      | черновик или нет                                 |
| `is_template`                | bool      | шаблон или нет                                   |
| `do_notify`                  | bool      | уведомлять <u>автора</u> о новых ответах или нет |
| `expire_at`                  | timestamp | дедлайн прохождения                              |
| `created_at`                 | timestamp | дата создания                                    |

**Заметки:**

- При реализации параметры `is_authorized_only`, `are_responses_limited_to_1` должны быть связаны между собой.
- Пользователи не должны уметь создавать шаблоны — у них будет возможность копировать свои опросы.

<a name="связи-между-сущностями"></a>
## Связи между сущностями

- `user` 1 — N `survey` (через `survey.author_id`).
- `user` N — N `survey` через `permissions` (`permissions.user_id`, `permissions.survey_id`, `role`).
- `survey` 1 — N `page` (через `page.survey_id`).
- `survey` 1 — 1 `completion` (через `completion.survey_id`).
- `page` 1 — N `question` (через `question.page_id`).
- `question` 1 — N `choice` (через `choice.question_id`).
- `user` 1 — N `response` (через `response.user_id`).
- `survey` 1 — N `response` (через `response.survey_id`).
- `response` 1 — N `answer` (через `answer.response_id`).
- `question` 1 — N `answer` (через `answer.question_id`).
